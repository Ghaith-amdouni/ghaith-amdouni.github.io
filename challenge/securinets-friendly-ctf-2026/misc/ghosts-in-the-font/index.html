Challenge

The player receives only invoice.pdf. It renders as an ordinary archival invoice, and copying the document or running pdftotext returns the same innocent text that is visible on the page.

Concept

PDF text has three separate identities:

  • the character code stored in the page content stream;
  • the glyph selected by the font encoding and drawn by the viewer;
  • the Unicode character returned through the font's ToUnicode map.

The invoice uses a custom encoding for its embedded FreeMono font. Every printable ASCII character has two valid codes:

For example, both 0x41 and 0xC1 are mapped to the glyph named A, and the ToUnicode CMap maps both codes to Unicode U+0041. They therefore look and copy identically even though their stored codes differ.

The /Differences array maps codes 0xA0 through 0xFE back onto the same glyph names used by printable ASCII. The /ToUnicode CMap performs the same double mapping for text extraction.

Solution

Decompress the page content stream and collect the hexadecimal strings rendered with the /FG font. For every byte, its high bit is the hidden bit; masking that bit away produces the innocent visible character.
