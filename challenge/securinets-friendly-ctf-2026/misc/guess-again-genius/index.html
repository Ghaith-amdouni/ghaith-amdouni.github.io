Player-facing content

The player receives only the remote endpoint. There are no downloadable files, technical clues, or hints. The service prints two six-digit verification codes and accepts one prediction for the next code.

The public description is intentionally sarcastic:

Two codes are already on the screen. Predict the next one, Professor Probability.

>

Go on. The machine could use a laugh.

Construction

Each connection creates an independent Python random.Random instance seeded with int(time.time()). It draws exactly three values using randint(100000, 999999), discloses the first two, and checks the player's input against the third.

The seed has one-second granularity. A solver records its local time when it connects and tests nearby timestamps. For each candidate it reproduces the first two calls. Matching both visible codes identifies the seed with overwhelming confidence, after which the third call predicts the required answer.

The weakness is the predictable seed, not a statistical defect in the displayed six-digit values. Two outputs are exposed so the correct nearby timestamp can be identified without ambiguity.

Intended solution

  1. Connect and record the two displayed codes.
  2. Enumerate Unix timestamps near the connection time.
  3. For each timestamp, create random.Random(timestamp).
  4. Reproduce two randint(100000, 999999) calls.
  5. When both values match, generate the third value and submit it.

The included organizer solver uses a ten-minute window to tolerate clock skew and manual delays.
